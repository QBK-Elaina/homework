Q1：为什么还要学习手写程序
我认为虽然现在AI可以代替绝大多数的程序任务，但是作为一位内容创作者，我们还是有必要至上能读懂AI生成的程序，因为AI的程序只是设计思路和逻辑的体现，只是一个工具，并不能代替人去做创意的产出。

举例，在我本科的学习过程中，我是在确保自己已经掌握了编程这项技能后才去使用AI的。在大二的项目中，我为了确保程序最后产出的效果和我的设计一致，坚持全程手写Unity的C#，在这过程中积累了足够多的逻辑经验。到了大三做毕设项目时，为了能更快的迭代玩法机制上的设计，我在确保AI能准确执行我想表达的设计逻辑后才会将程序任务交给AI。在测试过程中如果发现AI写的程序和我设计的不一致时，我会马上选择手写，为了确保作品效果的准确性。
先学会手写再使用AI这一过程中，这是一种“我可以不写，但不能不会”的感觉。不然哪天断网或者没有AI用了，那么设计师创作者就成了“哑巴”了。

正文：

在AI时代，每个人都可以很简单的使用AI工具写出代码，但在没有经过系统性的programing学习之前，我们都处于一个“知其然不知其所以然”的状态。我们只知道“程序”成功了，并不知道其背后的原理，甚至不知道这个成功程序的是否和自己设计的一样，是否和自己在给出AI提示词时脑内的“想象设计描述”一致。光是这一点，就很能说明基础的programing学习的重要性了。

在我的本科学习中，关于这种“先学会，再偷懒”的做法深有体会。
在大二的期末项目中，我提出了一种“折叠地图”的机制。我试着直接让AI按照我所描述的机制去设计并编程，但无一例外效果全都和我预想的有所偏差。
在尝试了一周后，我意识到无脑的去使用AI是无法做出项目的，所以我请教了教授，回到了手写程序。
在尝试手写程序后，我意识到我给AI的指令实在是太不清晰了，“在这个游戏中，什么是折叠”，直到我在手写的过程中开始拆分机制原理时，我才意识到AI单靠我给出的“折叠”提示词根本无法理解。在手写程序的过程中，我对拆解细分游戏机制功能愈发熟练，这是只是用AI无法提升的技能。于是，大二的整个后半学期，我每天都在分析原理机制然后手写修改程序，最后加起来写了超过5万多行的程序。
